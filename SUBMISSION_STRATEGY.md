# SUBMISSION_STRATEGY.md

## Title

# Signal Fracture — Chaos Engineering for Human Communication

## Subtitle

A multi-channel agent that deliberately fractures a team's information, detects the resulting contradictions, and reconstructs who knew what when.

## Positioning rules

Say:

- communication chaos engineering;
- separate role knowledge;
- causal contradiction;
- real heterogeneous channels;
- one shared handler;
- fictional drill;
- deterministic engine.

Avoid leading with:

- incident bot;
- emergency alerting;
- tabletop chatbot;
- notification system;
- generic roleplay;
- AI crisis manager.

## README opening

The first screen must show:

1. one-line pitch;
2. triangle/channel image;
3. 20-second explanation;
4. demo video;
5. proof that one handler serves three channels.

## Measurable result

Report actual demo values:

- channels connected;
- injects delivered;
- contradiction detection latency;
- knowledge divergence duration;
- reconciliation time;
- retries;
- duplicate consequences;
- rehearsal success rate.

Never invent metrics.

## Public usage evidence

Before submission, invite a small controlled group of classmates/friends to run one fictional drill.

Record:

- number of completed sessions;
- completion rate;
- median time;
- one safe feedback quote;
- defects found/fixed.

Do not run unsolicited outreach.

## Likely judge objections

### Existing tabletop platforms already exist

Response:

> They centralize participants. Signal Fracture tests the fractured information environment itself and reconstructs causal knowledge differences across real channels.

### Multi-channel is decorative

Response:

> The channel is part of each role's knowledge path. Delay, omission, threading, and delivery status alter the scenario.

### AI could hallucinate the exercise

Response:

> The LLM cannot alter facts or transitions. It only maps wording into a fixed choice. The scenario and contradiction engines are deterministic.
